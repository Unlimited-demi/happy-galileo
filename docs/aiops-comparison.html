Happy Galileo vs the Field

How a self-hosted, Docker-native AI-Ops workstation compares to Kubiya, Robusta, Keep, Sweep / Plandex, and Sentry — and where it stands alone.

happy-galileo · *.dev-server.datakrib.com · August 2026

What Happy Galileo actually is

None of the tools in the field bundle what this platform bundles. It runs on plain Ubuntu VMs with Docker — no Kubernetes required — and combines three layers that elsewhere require three separate products:

Layer 1 · Ingress

devctl + Caddy wildcard TLS

One command (devctl expose app 3000) yields an instant HTTPS URL. Zero host ports exposed; all traffic rides the private dev-net bridge behind Caddy.

Layer 2 · AI-Ops daemon

Detect & self-heal

Docker-socket health checks, a language-agnostic log-grammar classifier, and tiered remediation: L1 restarts, L2 network and Caddy resync — bounded, autonomous, audited.

Layer 3 · Escalation

Incident Dossier → coding agent

Application bugs are never touched autonomously. Stack trace, git diff, logs, and Playwright screenshots are packaged into a dossier and handed to OpenCode to fix the code.

Tool by tool

Robusta

Closest peer

Alert triage plus automated infrastructure playbooks — the same conceptual shape, but Kubernetes-only and stops at infrastructure. Happy Galileo covers the same ground for Docker-on-VM setups, a segment Robusta simply doesn't address, and goes one tier further by handing application bugs to a coding agent. Robusta is more mature on detection, though: it rides on Prometheus/AlertManager with a large library of enrichers, where Happy Galileo's health checker and anomaly classifier form a self-contained heuristic engine with no metrics backend.

Keep

Opposite bet

Keep is an alert router: it ingests alerts from monitoring tools you already run and triggers workflows. Happy Galileo made the opposite design choice — it is the monitoring source (HTTP probes plus the Docker socket), so there is nothing to integrate. Keep wins on flexibility: any alert source, arbitrary workflows. Happy Galileo wins on turnkey: run setup-server.sh and it's monitoring, with opinionated built-in tiers instead of YAML workflows the operator must author.

Kubiya

Different model

Conversational and hybrid-SaaS — their control plane, your runner. Happy Galileo is fully self-hosted with no vendor dependency, and it's a daemon, not a chatbot: it acts on its own schedule rather than waiting for instructions. Kubiya has far more integrations (Jira, Datadog, AWS); Happy Galileo has none, by design.

Sweep / Plandex / Aider

Complementary

These are the "AI fixes the code" half of the story. Happy Galileo doesn't compete with them — it slots one in. OpenCode plays that role today, and the Incident Dossier is the glue those tools lack: they need someone to feed them error context, and the dossier builder automates exactly that.

Sentry + agent integration

DIY analogue

Wiring self-hosted Sentry to a coding agent is the do-it-yourself version of Happy Galileo's Level-3 pipeline. Sentry captures richer runtime errors — in-process SDKs, breadcrumbs, release tracking — than log scraping ever can, but it requires instrumenting every application. Happy Galileo's classifier works on any container's logs with zero app changes: shallower signal, universal coverage.

Honest gaps

  • No metrics or trends. The daemon probes current state but keeps no time series, so gradual degradation — memory creep, latency drift — that Prometheus-backed tools catch will pass unnoticed. The fleet telemetry streamer is a start toward closing this.
  • Heuristic classifier vs. AI root-cause analysis. The regex grammars are fast and free, but Robusta and Kubiya run LLM analysis on failures. An optional LLM pass over the dossier before the OpenCode handoff would close the gap cheaply.
  • Battle-testing. Established tools have thousands of production deployments behind their noise filters and dedup logic; the noise-pattern list and incident dedup here will need iteration against real-world log diversity.
  • No Kubernetes path. Fine for the target — dev workstations and small fleets via Ansible — but it caps the addressable use case that Robusta owns.
Bottom line

Nothing in the field is a direct competitor. The closest description of Happy Galileo is "Robusta for Docker VMs, fused with a self-hosted ngrok/Coolify-style ingress, with a Sentry-to-AI-coder pipeline built in."

The tiered safety boundary — fully autonomous for infrastructure, dossier-and-escalate for code — is a genuinely distinctive design choice: the fully-autonomous tools lack it, and the PR-only tools can't match it on infrastructure.
